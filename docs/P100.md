# P100 fork: patch series and build notes

Upstream `ggml-org/llama.cpp` master `6050b467c` (b11887, 2026-10-25) = tag `p7-base`, plus:

- Kmic-68/llama.cpp `p100-optimizations` `d327bf1f0..7461904d` (MIT), ported as 5 squashed commits P7-2..P7-6,
  each with an `Origin:` trailer. Kernel design and tuning are theirs (see `NOTICE.md`).
- P7-7: padded speculative-verify fix (zeroed pad columns, scale-by-0 writes 0), so a NaN in an unused
  verify column cannot poison the recurrent state.
- P7-8 (a): compact KQ mask only on the qwen35 arch, so other hybrid graphs (Qwen3.8-Flash-Next) load.
- P7-8 (b): GDN in-place state gather copies its row index into a private device buffer (fixes an
  out-of-bounds read / Xid 13 on Flash-Next).
- Flash-Next / MoE patches (BF16 and K-quant P100 mat-vec kernels, pinned host experts, per-card MoE cache
  budget), all opt-in by env or compile flag.
- **Pascal (`sm_60` / `sm_61`) low-bit I-quant engine (`vecdotq-p100.cuh`, `mmvq.cu`)**:
  - Covers all 7 low-bit I-quant formats (`IQ1_S`, `IQ1_M`, `IQ2_XXS`, `IQ2_XS`, `IQ2_S`, `IQ3_XXS`, `IQ3_S`)
    across both `MUL_MAT` (dense, `n=1..8`) and `MUL_MAT_ID` (MoE), 100% bit-exact (`test-backend-ops` 100% PASS).
  - Cooperatively stages 1–8 KB codebooks once per CTA in shared memory using **32-bit Bank-Split SoA** (`lo[]` + `hi[]`
    for 64-bit IQ2 tables to avoid 2-way 64-bit bank conflicts; flat `uint32_t[]` for IQ3/IQ1).
  - Replaces emulated `__vcmpne4` + `__vsub4` + `ksigns` global lookups with a branchless 1-XMAD + 1-PRMT
    per-byte two's-complement sign-apply (exploiting that every IQ2/IQ3 grid byte is strictly in `[1, 62]`,
    guaranteeing zero cross-byte carry) and 3-cycle `__popc` parity sign decode.
  - Feeds `p100_mad16x2` (`XMAD`) on `sm_60` and hardware `__dp4a` on `sm_61`; uses `4 warps × 4 rows/warp`
    `split_rows` for `n=1` (`m >= 1024`, unfused) to amortize the shared codebook & `y_stage` across 16 rows
    and enable 4× activation CSE hoisting.
  - **Measured on Tesla P100-PCIE-16GB (`test-backend-ops perf`):**
    - `n=1` (`m=8704, k=5120`): `IQ2_XXS` `78.95 -> 63.76 us` (**+23.8%**), `IQ2_S` `85.50 -> 73.72 us` (**+16.0%**),
      `IQ3_XXS` `86.83 -> 68.99 us` (**+25.9%**), `IQ3_S` `92.40 -> 75.56 us` (**+22.3%**),
      `IQ1_S` `61.17 -> 48.70 us` (**+25.6%**), `IQ1_M` `77.20 -> 62.47 us` (**+23.6%**).
    - `n=5` (`m=4096, k=14336`, speculative verify / small batch): `IQ2_XXS` `252.04 -> 194.13 us` (**+29.8%**),
      `IQ2_XS` `290.83 -> 213.67 us` (**+36.1%**), `IQ2_S` `293.74 -> 211.83 us` (**+38.7%**),
      `IQ3_XXS` `294.16 -> 198.75 us` (**+48.0%**), `IQ3_S` `293.84 -> 194.82 us` (**+50.8%**),
      `IQ1_S` `209.78 -> 162.00 us` (**+29.5%**), `IQ1_M` `302.96 -> 272.53 us` (**+11.2%**).
- **Universal Nov 2026 Sync & Wave 7 Pascal (`sm_60`) Multi-GPU + `NVFP4` + GDN Engine (branch `p100-universal-2026`):**
  - Merged upstream `ggml-org/llama.cpp` `fa9f928f2` (2026-11-26) bringing full support for 2026 architectures
    (`inkling2`/`inkling2_loop` + fused `inkling2.cu`, `DFlash`/`DFlash2`/`DSpark`, `flint`, `lfm2moe`, `qwen35`, `gemma4`,

    - 10 new `STACK:0 SHARED:0 LOCAL:0` kernels (`ggml_cuda_ar_pascal_ddio_{f32,bf16wire,16}_kernel`,
      `ggml_cuda_ar_pascal_p2p_2gpu_f32_kernel`, dual-socket `ggml_cuda_ar_pascal_p2p_hier_4gpu_kernel` using `LDG.E.128`
      @ `10.18 GB/s` + cross-socket mapped-RAM BF16), `POOL_SIZE=4`, zero CPU `cudaEventSynchronize`, parallel per-peer

    - Beats NVIDIA NCCL on 4× P100 `-sm tensor` (`Qwen3.8-27B-UD-Q4_K_XL`, `-ac 715,1189`): `pp512` `404.8 -> 519.8` (**+28.4%**),

  - **Pascal `NVFP4` Engine + Branchless `ue4m3` (`common.cuh`, `vecdotq-p100.cuh`, `mmvq.cu`):**
    - Replaced CUDA's software `__nv_fp8_e4m3` helper on pre-Ada GPUs with a 4-op branchless IEEE-754 bit decode

      `QK=64`-tuned `rows=2, nwarps=1/2`).
    - `test-backend-ops` (`nvfp4`, `m=4096, k=14336`, `74/74` `MUL_MAT_ID` + all `MUL_MAT` PASS): `n=1` `100.94 -> 83.53 us` (**+20.8%**),

      `+6.8%` with `DSpark d=3` (`24.60 -> 26.28 tok/s`).
  - **Fused Split-K `Q8_0` GDN Gate (`mmvq-f16.cu`, `ggml-cuda.cu`) + `gdn-chunked.cu` 16B Alignment Guard:**
    - Fuses `MUL_MAT(alpha) + ADD + SOFTPLUS + MUL` & `MUL_MAT(beta) + SIGMOID` into 1 launch (`-240..288` launches/tok,
      streaming 4 weights/step -> `STACK:0` for `NC=1..8`), lifting `Qwen3.8-27B` 4× P100 plain decode `42.86 -> 44.07 tok/s` (**+2.82%**).
    - `gdn-chunked.cu` 16-byte alignment guard passes `103/103` `GATED_DELTA_NET` backend tests.
  - **Pascal `sm_60` MoE Prefill, Graph Defaults, Tied Head Sharding, and Narrow `GET_ROWS` (`mmid-f16-p100.cu`, `ggml-cuda.cu`, `gemm-fold.cu`, `getrows.cu`, `llama-model.cpp`):**
    - Native FP16-product / FP32-accumulate grouped GEMM for `MUL_MAT_ID` (`STACK:0`, passes `1105/1105` backend op tests across all `BN` tile widths) replaces emulated-DP4A `MMQ` on GP100 (`sm_60`), with zero-VRAM on-the-fly FP16x2 unpack for all 15 primary quant types plus an automatic `ggml_get_to_fp16_cuda` pre-dequant path for `IQ1`/`IQ2`/`FP8` and future quant types (`GGML_CUDA_MMID_F16=0` disables).
    - Default `GGML_CUDA_GRAPHS_PRE_VOLTA=3` on Pascal (`sm_60`/`sm_61`) with fixed `MUL_MAT_ID` (`src1->ne[2]`) and 2D weight (`quantized|F16|BF16`) single-token detection.
    - Shards duplicated tied `output` LM heads across GPUs in `-sm tensor` (`Gemma-4` 262K vocab).
    - General coalesced narrow-row `GET_ROWS` (`k_get_rows_float_narrow_vec` and `k_get_rows_float_narrow`, `239/239` tests pass, `STACK:0`) cuts `Inkling-2-Mini` relative-position bias gather from `505 ms` to `~8 ms`.
    - Disables dead 4-way `xchg_chunks` slicing in `gemm-fold.cu` when internal AllReduce is active (`ctx.xchg_peer == nullptr`) and extends fused GLU prescale to `GeGLU` and arbitrary FFN widths (`K > 11264`).
  - **Multi-GPU High-Draw Chassis Power Envelope Note (4× P100 `-sm tensor`):**
    - On 4× P100 `-sm tensor` systems where sustained ~500 W 4-GPU load trips motherboard/PSU external `BD PROCHOT` CPU
      throttling, locking application clocks to `sudo nvidia-smi -ac 715,1164` retains **100% `715 MHz` / `732 GB/s` HBM2**
      at `~85–95 W`/card and prevents CPU throttling (`18.5 -> 44.1 tok/s` plain, `60.8 tok/s` w/ MTP on `Qwen3.8-27B`).
      Use `-ac 715,1328` for 1×/2× P100, `-sm layer` runs, or chassis with ample PSU headroom.

## Build (sm_60 ONLY: a multi-arch build silently gets upstream's kernels)

```
cmake --preset p100
cmake --build --preset p100        # llama-server + llama-bench in build-p100/
```

The same without the preset:

```
cmake -G Ninja -B build-p100 -DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=60 -DCMAKE_BUILD_TYPE=Release \
      -DLLAMA_BUILD_TESTS=OFF -DLLAMA_BUILD_EXAMPLES=OFF
cmake --build build-p100 --target llama-server llama-bench
```

For the kernel tests configure with `-DLLAMA_BUILD_TESTS=ON` and build `test-backend-ops`.
The Pascal paths select themselves by `__CUDA_ARCH_LIST__ == 600` (`GGML_CUDA_MMVQ_PASCAL` in mmvq.cu).
Flash-Next's own switches (`-DGGML_CUDA_P100_VMAD`, `GGML_CUDA_P100*` env) are off by default.
